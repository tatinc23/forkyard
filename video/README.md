# Forkyard film and voiceover (v3, 2026-10-14)

Coded film segments plus an AI voiceover for the 5 to 6 minute demo video. Pipeline: `timeline.js` + `facts.js` + `vo.json` -> `film.js` painter (`window.seek(t)`, a pure function of t) -> `render.mjs` (headless Chrome, 1920x1080, 60 fps) -> `audio.mjs` (procedural bed + cues) -> `tts.mjs` (voice) -> `mixvo.mjs` (duck, loudnorm, mux).
Theme: "a new way for hundreds of thousands of agents to work on changes concurrently". It is on screen by 4.6 s and the new scale scene (5 to 100 agents, merge tree vs queue, "you watch exceptions") is the centre of the opening.

All 1920x1080, 60 fps, H.264 + AAC 192k, VO over the music bed (bed 12 dB under the voice), -16 LUFS. Captions are burned in and are the VO lines.

## Voice
`@cf/deepgram/aura-2-en`, speaker `orion`, via the Workers AI REST API (`/accounts/<id>/ai/run/<model>`, `{text, speaker, encoding: linear16, container: wav}`). Verified live in the Cloudflare docs on 2026-10-14 (Aura-2 listed as text-to-speech, parameters speaker/encoding/container/sample_rate, $0.03 per 1k characters; `aura-1` and `melotts` are the other TTS models). Chosen by analysis (I cannot listen): I rendered the same technical line in 10 aura-2-en speakers plus aura-1 and melotts and transcribed each back with Whisper large-v3-turbo. `orion` returned the line exactly, including "Forkyard", "Artifacts", "Durable Object", "x402" and "Base Sepolia"; `melotts` misheard "GitHub" ("Jithub"); `apollo`, `atlas`, `luna`, `arcas`, `aries` and `hermes` each dropped or garbled a word. `orion` is documented by Deepgram as a calm, approachable male voice (from memory of their voice list, not re-verified), and measured pace was 2.2 to 3.3 words per second (about 135 to 200 wpm; the 41 lines average about 2.6 w/s). **A human should listen once.**
Credentials: `tts.mjs` reads `CLOUDFLARE_API_TOKEN` from the environment, else a 1Password `op item get` call; it never prints or writes the token. In this session `op` hung (no response), so the token came from the 12 h secrets cache sourced into the shell.

## Re-render
```
cd video && npm install
node tts.mjs                    # only changed lines are re-synthesised
node gen-docs.mjs               # voline.js, captions, VO_SCRIPT.md (prints any line overruns)
for s in open hood close; do node audio.mjs --seg $s; node render.mjs --seg $s --workers 4; node mixvo.mjs --seg $s; done
# teaser: ffmpeg -f concat -safe 0 -i list.txt -c copy out/master_16x9.mp4   (list = seg_open.mp4, seg_close.mp4)
```
About 10 min for the opening, 4 min hood, 1.5 min close on this Mac. Requires Google Chrome at `/Applications/Google Chrome.app` and ffmpeg at `/usr/local/bin/ffmpeg`.

## Refresh numbers (when the pinned production run exists)
Edit `SCALE` in `facts.js` (agents, crews, forks, commits, conflicts, resolved, ms, job), set `REVIEW.illustrative = false` with the run's flagged/auto counts, update `SOURCES.md`, then re-run the loop above (VO lines never speak a null number; only `CREW.commits` is spoken).

## What was tested (v3, 2026-10-14)
- **Format:** all three segments 1920x1080, 60 fps, H.264 + AAC; durations by ffprobe: open 96.000 s (5760 frames), hood 43.000 s (2580), close 15.600 s (936), master (open + close) 111.621 s. Full decode of each is clean (`verify/decode.txt`).
- **Frame determinism:** `node determinism.mjs --seg open 12 40 52 74 88` and `--seg hood 8 26`: frames are identical across separate Chrome launches and seek orders, with one caveat: in two runs a single frame (open t=52, then t=74) differed from its re-run by exactly **one pixel** (865,558 in the "No." card), and the same frame was identical on re-runs. I believe it is a rasteriser anti-aliasing flip, not state; I did not find a cause. The painter itself uses no clocks or randomness (hash-based jitter only). Evidence: `verify/determinism_open.txt`, `verify/determinism_hood.txt`.
- **Loudness (shipped AAC):** open -16.0 LUFS / LRA 4.9 / true-peak-limited at -1.5 dBFS; hood -16.0 / 5.3 / -1.5; close -16.1 / 4.9 / -1.4 (`verify/audio-analysis.txt`, `verify/loudnorm_*`). No silence longer than 0.5 s below -60 dB in any segment. Bed 12 dB under the voice while it speaks (rises 6 dB in the gaps), cues 6 dB under; measured by the mixer (`mixvo.mjs` prints the dB figures).
- **Flashes:** per-frame mean-luma change: open 0.71 % max, hood 1.23 %, close 0.05 %; 0 frames above 10 % (`verify/flash.jsonl`).
- **Contrast:** tokens unchanged from v2; all text pairs >= 4.5:1 (`verify/contrast.json`). New shapes keep the 3 px ink edge; orange text only as deep orange.
- **Colour is never the only signal:** 100 agents are told apart by shape + crew position (and flagged agents by hatching and a dashed ring), not colour; approved / flagged / conflict use glyphs and hatching.
- **Captions vs VO:** burned-in captions are generated from `vo.json` with the measured TTS durations (`captions_*.srt`, `VO_SCRIPT.md` fit check: no overruns).
- **Reviewed by eye:** stills at every beat (`verify/s3/`, `verify/h/`, `verify/c/`, `contact_open.png` from the final MP4). Fixed during review: tree dots touching, conflict card overlapping the panel footer, "Job" chips overlapping their subtitle, "GLM-5.3" caption splitting at the decimal point, real-run label colliding with the levels label.
- **Not re-run for v3:** reduced-motion cut (the `?reduced=1` painter path still exists but was not rendered), a phone-width (390 px) review, the independent design-review pass.
